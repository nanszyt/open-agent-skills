# 合思工作流 JS 节点需求收集与提示词标准模板

当用户需要新写一个合思工作流 JS 代码节点时，若上下文信息不完整，按以下模板快速向用户对齐入参、数据结构与出参契约。

---

## 1. 必填信息清单

1. **沙盒版本**：确认是否为「JS 节点（新）」（默认按兼容 **ES6 / ES2015** 编写；仅在明确要求时使用 ES2020 `?.`）。
2. **注入入参列表**：
   - 每个变量在节点入参配置中的**精确变量名**、数据类型、示例值。
   - **变量名合法性核查**：合思会将变量名直接拼接为 `const <变量名> = __inj["<变量名>"];`。若变量名含空格（例如 `u 首期时间`）或连字符（`a-b`），会导致语法报错！遇到此类名称必须提醒用户在工作流节点配置中改名为合法标识符（如 `u首期时间` 或 `firstPeriodTime`）。
3. **真实报文样本（若有）**：优先让用户提供一次调试输出的 `debug_json` 或原始入参 JSON，避免猜测字段前缀（如 `E_<entityId>_字段名`）和嵌套层级（如 `data.dataLink.id`）。
4. **出参对象结构**：确认最终 `return { ... }` 需要返回的字段名（Key）及其类型（字符串 / 数字 / 数组 / 对象）。

---

## 2. 标准化提示词结构（供人工或跨模型调用复用）

```markdown
目标：为合思费控工作流 JS 代码节点（支持 ES6 语法的函数体沙盒）生成可执行代码。

### 1. 运行环境与约束
- 语言：现代 JavaScript（ES6/ES2015，使用 const/let/箭头函数，避免顶层 export/import 与函数外包装）。
- 变量注入：外部上下文直接注入已声明变量，严禁修改入参原始引用。
- 返回值：最终必须通过 `return { ... };` 返回一个 JavaScript 对象（Map），键名与节点出参一一对应。

### 2. 外部传入变量定义
| 外部变量名（合法 JS 标识符） | 类型 | 说明 | 示例值 |
| --- | --- | --- | --- |
| `<varName>` | `<type>` | `<desc>` | `<example>` |

### 3. 代码逻辑与边界规则
1. [核心业务逻辑]
2. [空值 / 异常输入 / 数组 null 元素的兜底规则]
3. [金额精度（转分计算）或日期时区（UTC+8）要求]

### 4. 最终输出要求
仅输出可直接粘贴进合思 JS 代码节点的完整代码块及出参映射说明。
```
